# thlyrics（东方同人曲 学唱机）

从**东方同人曲的歌词**里学日语词、练跟唱的小工具。数据管道 + 纯静态前端，不需要后端。

灵感来自 [NakayamaFesta/popipa-tango-dreamer](https://github.com/NakayamaFesta/popipa-tango-dreamer)（Popipa 单词机），
但东方同人曲的结构不同，所以数据模型换了一套：

| | popipa 单词机 | 本项目 |
|---|---|---|
| 键 | 一首歌 = 一份歌词 | 原曲 ↔ 曲目（社团/专辑）↔ 歌词 |
| 词表 | 人工整理 | 从歌词自动分词（kuromoji）+ 辞书形还原 |
| 时间轴 | 无 | LRC 自带时间轴（THBWiki 提供的曲目有） |
| 读音 | 罗马音为主 | 假名为主 + 罗马音可开关 |

## 现在能做什么（词汇入手）

**曲库 = 你自己导入的歌**（站上不带任何内置曲目）：在曲库页粘网易云链接 / 分享文案 / ID，
支持**歌单、专辑、单曲**，手机分享出来的 `163cn.tv` 短链也能直接认。
导入后按歌词自动分词、标日/JLPT 分级、词性配色、逐词罗马音、单句循环——整套学习功能都跟着你的歌走。

- **学词页（默认首页）**：直接给"今天学哪些词"，按《新版 标准日本语》课次 → JLPT 等级 → 曲库常见度三级排序（从易到难），
  可按标日范围 / JLPT 等级 / 词性筛选，一键标"已掌握"。
- **单曲页**：**先列出这首歌用到的全部词**（按标日课次排，可按"标日收录 / 未收录 / 词性"筛），
  每个词能听发音、点"去这句"直接跳到歌词里它出现的那一句并开始单句循环。
- **分词**：导入时由自建后端用 kuromoji(IPADIC) 做形态分析（Viterbi，带辞书形/读音/词性），
  再和站内词表（1358 曲库词 + 5065 条《标日》词，共 6423 词带中文释义）对齐。
- **歌词**：按词性分色（名词/动词/形容词/形容动词/副词/助词），每个实词下面挂它的中文释义（词级中文，可一键收起），
  罗马音与中文都锁在**各自那一句的块里**，不会串行；点词看读音释义，点句子从那句开始循环。
- **播放**：进单曲页就把音频地址解析好；本浏览器播过一次之后，进页面即开始提前缓冲，点播放几乎立刻出声。
  签名地址在有效期内缓存复用（内存 + localStorage），不再每点一次重取。
- **检索**：一个输入框搜词 / 释义 / 曲名 / 社团 / 专辑 / 原曲，结果按"词 / 曲目 / 原曲"分组。
- **生词本**：已掌握的词、自己改过的释义都存在本机，可导出/导入 JSON。
- **曲库**：默认按入库时间倒序，可按标题五十音升/降序；专辑页是两列网格（封面 + 专辑名），
  点进去筛这张专辑的歌；能标「收藏」「会唱」并按它们筛。
- **我的**：账号（头像可换）、主题（深色 / 暖白 / 跟随系统，顶栏头像菜单里有黑白开关）、
  显示开关、同步、数据导出导入、**分享码**（把歌单/专辑/单曲的来源发给别人，别人粘进来自动导入）。
- **管理员**：独立页面，列 / 删 OSS 上的文件（账号数据、音频、分词词典）。

### 音频与解析

- 音频/歌词优先走自建后端（阿里云函数计算，见 `ops/`）：`/api/audio` 取网易云可播直链、
  `/api/lyric` 取歌词与翻译，避免第三方公共接口限流；失败才回落到 `music-api.gdstudio.xyz`。
- 直链是临时签名的（约 20 分钟），前端每次播放前会重新解析（18 分钟内复用缓存）。
- 不下载、不落盘：音频始终在线流播，服务器和本机都不存 mp3。

### 难度分级的数据来源

| 用到的信号 | 来源 | 许可 |
|---|---|---|
| 标日课次（初级上 1-24 / 初级下 25-48 / 中级上 49-64 / 中级下 65-80） | [L-hikari/japanese](https://github.com/L-hikari/japanese) | MIT |
| JLPT N5-N1 等级 | [Bluskyo/JLPT_Vocabulary](https://github.com/Bluskyo/JLPT_Vocabulary)（原始数据 tanos.co.uk） | MIT |

标日词表里的动词是「ます形」，脚本会还原成辞书形再和本项目词表对齐；
对齐只用「词形完全一致」或「纯假名写法按读音一致」（避免 はやし(林) 撞上同音的 囃子 这种误标）。

## 数据来源

- 歌词：**THBWiki 歌词服务** `https://lyrics.thwiki.cc`（LRC 格式，带 `ti/al/ar/cv` 元数据）
- 搜索：`https://thbwiki.cc/api.php?action=opensearch&namespace=512`（namespace 512 = 歌词命名空间）
- 两者都是公开接口。**歌词版权归各社团 / 原作者所有，仅供个人学习，请勿传播或商用。**

## 目录结构

```
thlyrics/
├── data/
│   ├── raw/            # 抓下来的原始 .lrc（每首一个文件）
│   ├── index.json      # 解析+分词后的完整数据集
│   ├── queries.txt     # 抓取用的关键词清单（每行一个，可自己加）
│   └── fetch-log.json  # 抓取日志（成功/失败/URL）
├── scripts/
│   ├── fetch-lyrics.mjs  # 抓歌词
│   ├── build-index.mjs   # 解析 LRC + 分词 + 生成 JSON
│   ├── kana-romaji.mjs   # 假名 -> 罗马音
│   └── serve.mjs         # 本地静态服务
└── docs/                # 前端（GitHub Pages 从 /docs 发布，无构建无依赖）
    ├── index.html
    ├── app.js
    └── data/index.json + covers/
```

## 用法

```bash
# 0) 依赖（只需要分词和罗马音用的包）
npm install

# 1) 抓歌词：按关键词搜索并下载
node scripts/fetch-lyrics.mjs --query "少女綺想曲" --limit 5
node scripts/fetch-lyrics.mjs --from data/queries.txt --limit 40   # 批量
node scripts/fetch-lyrics.mjs --title "幽雅に咲かせ、墨染の桜（トマト組）"  # 精确抓某一个

# 2) 生成数据集（加 --covers 会顺带下载专辑封面）
node scripts/build-index.mjs --covers --stats

# 3) 本地打开前端
node scripts/serve.mjs 8848     # 然后访问 http://127.0.0.1:8848/
```

参数说明：
- `--delay` 抓取间隔毫秒数，默认 1200，别调太小（对 wiki 友好）
- `--force` 已存在的文件也重新抓
- `--lang all|ja|zh` 取哪种语言的 LRC（默认 all）

## 前端功能

- **歌词**：按原曲分组的曲目列表；进曲目后有
  - 逐行朗读（浏览器日语 TTS，点句子也能单读）
  - 点任意词弹出读音 / 罗马音 / 词性 / 在库里出现多少首
  - `只高亮没学的词` 开关、`隐藏罗马音` 开关
  - 标记「已能脱稿」
- **单词卡**：卡片翻转（日文 → 假名 + 罗马音 + 词性 + 歌词里的活用形），
  间隔复习 1 / 3 / 7 天，连对 3 次算掌握；空格翻面、←→ 判对错
- **词表**：全库词表，按出现曲数排序，可搜词/读音/罗马音
- **进度**：掌握数、连续学习天数、错得最多的词；进度导出/导入 JSON

进度存在浏览器 localStorage，换设备用「导出进度」带走。

## 数据结构（docs/data/index.json）

```
stats      统计（曲目数/词表数/有时间轴的曲目数…）
originals  [{ name, tracks[] }]            原曲 -> 该原曲下的曲目
tracks     [{
  id, title, base, artist, album, coverFile,
  timing,                                 是否有真实时间轴
  lines: [{ t(秒), text, jp, romaji, segs }]
  vocabIds                                这首歌用到的词表 id
}]
vocab      [{
  id, word(辞书形), surface, reading(假名), romaji, pos, count,
  tracks[], forms{ 活用形: {readingHira, romaji, tracks[]} }
}]
```

`segs` 是分词结果，`{s:表面形, w:是否值得学, b:辞书形, l:词条读音, r:表面形读音, y:罗马音, p:词性}`。

## 音频与译文（网易云）

- 音频地址走公开中转 music-api.gdstudio.xyz（Meting 系），**每次播放前按需取一次**，因为网易云给的地址是临时签名的。
- 匹配方式：多轮搜索（曲名 / 曲名+社团 / 专辑 / 专辑+曲名）打分挑候选，**再用「网易云歌词 vs THBWiki 歌词」的一致性做校验**，
  一致度低于 45% 的一律不挂音频，避免播错歌。当前 44 首里 10 首通过校验。
- 没匹配上的可以自己绑：前端里展开「音频来源与设置」，把网易云那首歌的链接或数字 ID 粘进去即可（只存你自己的浏览器）。
  也可以在 data/netease.json 里手工写 {"matches":{"t3":{"nid":"123456","status":"ok"}}} 后重跑管道。
- 中文翻译：网易云的 tlyric（逐行），按时间戳对齐到日文行上。

## 释义（三种来源，优先级从高到低）

1. data/meanings.json —— 手工释义（自己补，最高优先）
2. data/meanings.auto.json —— 用「已有译文 + 词对齐」推断（scripts/align-meanings.mjs，覆盖少但语境准）
3. MyMemory 机器翻译（scripts/fetch-meanings.mjs，覆盖全但质量参差；可疑的会标 meaningCheck，前端提示「可能不准」）

每个词还挂了 1~3 条**真实例句**（日文 + 该句中文），点词就能看到。

## 单句循环（跟唱用）

- 点任意一句歌词：音频跳到那句并循环，到下一句开始前自动跳回句首
- 播放条：⟨ ⟩ 切上一句/下一句，1.0x 循环切换 0.6 / 0.7 / 0.8 / 0.9 / 1.0 / 1.1 倍速
- 快捷键：空格播放暂停、↑↓ 切句、L 开关循环
- 本地音频（自己的完整版）可以直接选文件，存在浏览器 IndexedDB 里


## 释义是怎么来的（重要）

1380 个词的释义**全部是手工翻译**，存在 data/meanings.mine.json 里（按词形做键）。
改法有两种：

1. 页面上点任意词 -> 「改释义」-> 写你的版本 -> 回车。改动只存在你自己的浏览器（localStorage）。
2. 直接改 data/meanings.mine.json，然后重跑 node scripts/build-web.mjs，所有人都能看到。

优先级：前端手改 > data/meanings.mine.json > 机器翻译（data/meanings.json）> 词对齐推断（meanings.auto.json）。
后两个只是兜底，正常不该被用到。

## 已知限制

- **读音还原不是词典级**。动词活用形 -> 辞书形的还原是自己写的规则（kuromoji 的 `base_form`
  对五段动词经常给活用形、对一段动词给词干），绝大多数正确，但个别词（如「経つ」「縫う」
  这种在歌词里只以促音便出现的）读音可能不准。发现错读直接改 `vocab.json` 对应条目，
  或者给 `build-index.mjs` 的词表加手工覆盖表。
- 只有 12 / 44 首的 LRC 带真实时间轴，其余是全 0；所以没做卡拉OK级同步，只做逐行朗读。
- 时间轴 = 音频对齐没做（需要本地音频文件）。
- 中文释义还没接（下一期可接 JMDict / 词典 API 或手工补）。
- 纯片假名外来语、纯英文行暂不进词表。
