# PLAN：UI / 交互重做（待开发）

状态：**待开发**（用户已点头「UI重做」）
依据：用户原话「特别丑，页面做的特别丑」「务必干净简洁清晰易用」
调研：联网查了 20+ 个来源（Material 3 列表规范、Apple/Spotify 迷你播放条、CJK 排版、Apple Music Sing 的聚焦歌词、WCAG 对比度、触摸目标等）

## A. 结构（信息架构）

1. 一屏一个主任务，删掉所有「顺便放一起」的内容（渐进披露）
2. 顶部只留标题 + 搜索图标（点开才出现输入框），省一屏垂直空间
3. 三个大 tab 换成紧凑分段控件：学词 / 曲库 / 生词本
4. 底部改**迷你播放条**（封面小图 + 曲名 + 大播放键，48px 高），上滑展开全屏播放页
5. 全屏播放页 = 跟唱页：整屏只有歌词，当前句放大居中，其余句降到 55% 不透明度
6. 单曲页「词汇 / 歌词」改为页内分段切换（**默认停在词汇**，符合「先把歌里的词列出来」）
7. 播放状态永远在底部可见、跨页面不打断（现已正确，保留）

## B. 视觉

8. 去掉卡片边框与色块，改用分隔线 + 留白分组（Material 3 列表）
9. 4/8 间距体系；字号层级只留 3 档（标题/正文/注释）
10. 深色底只保留一个强调色（当前句 + 主按钮）；词性颜色只出现在词上
11. 日语正文 17~18px / 行高 1.8；中文 13px / 1.6；罗马音 11px 等宽
12. 对比度全部 ≥4.5:1；助词不再用那么灰的色
13. 难度从「三个边框标签」改成点阵/进度条（●●○○）
14. 每行只留 3 个信息（词、读音、释义），其余进详情

## C. 交互（含「只能一句一句播」的修复）

15. 触摸目标 ≥44px，主操作在拇指区
16. **点句子 = 从这句继续往下播（不循环）**；双击/长按 = 单句循环（显式）
17. 单句循环默认关闭；开着时播放条醒目显示「单句循环中」+ 一键退出
18. 播放条永远显示「整首 / 单句」模式，可切换
19. 骨架屏 + 空态文案，杜绝「空白像坏了」
20. 缓冲/已缓存状态可视化（小圆环进度）
21. 动画克制：只在换句定位时滚动，不整页晃
22. 键盘快捷键保留（空格、↑↓、L）
23. 首进给一句可关闭的引导

## D. 加载性能（配合 1 秒目标）

24. `docs/data/index.json` 现在 1.9MB（gzip 337KB）→ 拆成「曲目列表（小）+ 按需加载单曲歌词」
