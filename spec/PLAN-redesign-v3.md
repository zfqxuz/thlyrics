# 重新设计 v3（按 GPT 的 16 条建议）

来源：用户 2026-10-14 深夜把 ChatGPT 的评审截图发过来（16 条建议 + 5 条"AI 味"成因 + 一张线框 + P0/P1/P2 顺序）。
本文件是执行清单，**做一条勾一条**，别再凭感觉改。

## 一、16 条建议（原文要点）

1. 让一个核心任务成为页面主角：首屏只突出「找歌 → 选歌 → 开始学唱」，其他功能是辅助入口
2. 歌词区是视觉中心：歌词占主要空间，当前句突出、上下句弱化；歌名/原曲/社团在歌词上方；操作围绕歌词
3. 别让学习模式变成一排开关：默认只给日文原文 + 必要读音，中文按需展开，罗马音是辅助；选中状态明确
4. 统一播放器：播放、进度、上一句、下一句、倍速、循环模式收进一个播放器区域，状态要持续可见
5. 搜索要帮用户找歌：模糊搜索，结果里显示曲名/社团/原曲/有无歌词；空结果给可执行建议
6. 生词学习融入歌词：点词后出紧凑词汇卡，按需展开释义/读音/上下文/掌握状态，低频操作进更多菜单
7. 生词本要有学习闭环：复习、再听原句、回到歌曲上下文、掌握度筛选
8. 音频配置移出主界面：网易云 ID/本地音频/OSS 属于技术配置，收进「音频设置」或歌曲的更多操作
9. 空状态/加载/错误要有真内容：不要用破折号占位，直接说「还没选歌」「暂无歌词」「尚未绑定音频」并给下一步
10. 视觉只走一条路线：克制（深墨蓝 / 暖白 / 纸张 / 唱片目录），别同时堆渐变、发光、玻璃拟态、卡片阴影
11. 建立字体与间距规则：标题/歌词/注音/译文/元数据/按钮各一档字号；间距用少量统一尺度
12. 优先手机：窄屏优先当前歌词 + 播放控制 + 最常用动作，低频配置进抽屉；测长歌词/横屏/软键盘
13. 歌词时间轴与音频直接联动：播放自动高亮、点歌词跳转、拖进度同步；只在需要时给精细校准
14. 交互要有反馈：保存释义、绑定音频、开启循环、加载歌词都要有明确可见的结果
15. 曲库像音乐目录，不是数据库查询结果：以曲名为主，社团/原曲/专辑为次级；没有真实素材就别放封面卡
16. 下次回来能继续：记住最近学习的歌、播放位置、模式；并说清哪些数据在本机、哪些同步到别的设备

## 二、"AI 味"的五个成因（自查用）

功能平铺 · 控制项比内容更抢眼 · 过度模块化 · 装饰性设计多于信息设计 · 没有真实使用流程。

## 三、改造顺序（GPT 给的 P0/P1/P2）

- P0 重组首屏，突出歌词与播放 → 用户更快开始学习
- P0 整合播放器和学习模式 → 降低操作复杂度
- P0 重新设计空状态、加载和错误反馈 → 减少困惑
- P1 改造搜索结果与曲库 → 更容易找到歌曲
- P1 将词汇操作整合为上下文面板 → 学习流程更自然
- P1 统一字体、间距、颜色和按钮规范 → 提高整体视觉一致性
- P2 完善移动端布局与键盘操作 → 提升多设备可用性
- P2 增加学习进度与继续学习 → 提高长期使用体验

## 四、当前进度

### 已完成（2026-10-14 深夜，E2E 105/105，已上线）
- 视觉体系（10/11 部分）：墨蓝底 + 暖白纸 + 一点朱红；**删掉渐变/发光/玻璃拟态**；
  字号固定六档（--fs-hero/title/lyric/body/sub/meta）；按钮分主/次/危险三档
- 首屏（1）：新增 `#/home` 首页——大搜索框 + 「正在学习」卡（继续学唱 / 换一首 / 导入歌单）
  + 三个小入口（曲库/学词/生词本）+ 「今天这几个词」一条；首页隐藏全局 tab 行（避免两排入口抢注意力）
- 播放器与学习模式（3/4）：三个显示开关收进「显示」抽屉（默认收起，状态写「开/关」）；
  播放控制收成一条：进度 + 上一句/播放/下一句 + ［整首|单句循环］· 倍速 · 显示；
  循环状态在分段控件上持续可见
- 不跳屏（2 的前提）：换当前句时所有歌词块高度不变（E2E 硬断言）；当前句靠加粗+亮色+左侧朱红条突出，
  **不放大字号**（放大字号会把整屏顶上去，踩过坑）
